# 测试用自写的 DOM 替身，不引入 jsdom

本插件大半的逻辑写在 DOM 补丁上：找 tab、读锚点、改样式、按鼠标拖拽。要检查这些，测试需要一个 DOM。仓库选择**自己写一个最小替身**（`test/helpers/dom.ts`，约 500 行），而不是引入 jsdom 或 happy-dom。

两条理由都不是"省依赖"：

**一、与生产代码共用同一个结构类型。** 这个替身实现的是插件自己的 `DocumentLike` / `ElementLike` 结构类型，所以生产代码与测试跑的是同一份实现。若换成第三方 DOM，就意味着生产代码对着真实 DOM 写、测试对着第三方 DOM 跑，中间隔一层适配，而这层适配会漂移，对一个靠 DOM 补丁活着的插件，这正是最不能承受的失败。

**二、能只实现被允许触碰的那一部分。** 替身只提供插件预算内的 DOM 子集，于是"某个补丁伸手去碰了不该碰的东西"会在测试里**失败**，而不是在用户浏览器里才暴露。选择器解析同理会刻意维护自己的边界（标签、属性存在性、属性精确值/子串、后代组合、`:not([attr])`），遇到不支持的形态直接抛错，而不是静默地什么都匹配不到。

代价是这 500 行本身要维护，且它不会覆盖真实浏览器的行为差异，所以"长相与手感"这类只能靠眼睛看的部分明确不写测试（见 `AGENTS.md`：UI 编辑不靠测试卡）。这个取舍的边界是：**逻辑靠替身，观感靠截图**，两者不互相冒充。
