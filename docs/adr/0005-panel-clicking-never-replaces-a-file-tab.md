# 只有文件列表 tab 借出自己的槽位，文件 tab 的槽位永不外借

同一个"点一行文件"的动作，在两种家里有两个不同的正确答案：

- 在**文件列表 tab** 里点一行：借这个 tab 的槽位，让目标文件顶替它（原地替换）。这样文件列表不再与它打开的文件分居两个 tab。
- 在**文件 tab** 里、面板停靠在一侧时点一行：面板不走，文件内容在该 tab 内原地切换，这样可以连续点开下一个文件。

第二条的理由是面板的常驻性：它存在的意义就是让读者连续浏览，一旦随宿主 tab 一起消失，这个意义就没了。所以替换的许可被收紧成两个条件同时成立：**当前 tab 停靠着、且当前 tab 就是文件列表 tab**（`src/client/features/file-panel/open-file.ts` 的 `planOpenFile`）。这也符合规格对"原地替换"的限定：它是给文件列表 tab 用的，不是给文件 tab 用的。

判定是一个只看"已开了哪些 tab、当前 tab 是哪个"的纯函数，因此这条规则不依赖浏览器就能被检查。实测中它曾被反向踩中过：浮动 tab 被当成停靠 tab，于是文件 tab 的槽位被借走（`a54d119`）。这说明**摆放状态是这条规则的一部分**，不是无关的实现细节。

## 已知未落实：聚焦已开文件时仍会关掉当前文件 tab

`planOpenFile` 的 focus 分支（`open-file.ts:100-107`）目前对所有 `current` 无条件产出 `closeTabIds`，测试也按此断言（`test/features/file-panel/open-file.test.ts:142-157`）。于是从文件 tab 点开一个**已经打开**的文件时，当前文件 tab 会被关掉，面板随之失去宿主。这与上面第二条规则冲突，也不符合规格对"关掉当前文件列表 tab"的限定。

记录在此，避免后来者把它当成刻意设计。修法是把关闭条件收紧到"当前 tab 就是文件列表 tab"，并同步改那条测试。
