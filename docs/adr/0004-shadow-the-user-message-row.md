# 遮蔽用户消息行，换取附件引用

复制一条消息要带走它的附件，但屏上的 DOM 不携带附件身份：图片是临时的 object 地址，文件连地址都没有。一条消息的持久附件引用只存在于它渲染器背后的节点数据里，而那个数据**只对拥有渲染器的代码可见**。

因此本插件以 `extension` 档遮蔽用户消息行的渲染器，复刻这一行的外观与行为，并从节点数据里取出附件引用、组装剪贴板载荷。被遮蔽的是宿主那一行渲染器，宿主插件本身仍在运行。

代价明确：接管一个渲染器就要把它原本的职责整套接过来（右对齐气泡、内容区、动作行），并受到"结果必须与被替换的东西难以区分"这条约束的检验。实际的缓解办法是**只接管外层**：气泡内部仍调宿主自己的 `conversation.chat.user.content` Factory 渲染，只有动作行与外层 flex 列由本插件重述（`src/client/features/message-copy/row.ts`）。

被否掉的替代方案是**纯 DOM 补丁**：只加一个复制按钮，不遮蔽任何东西。它做不到，因为附件引用在 DOM 里根本不存在，这正是要解决的问题本身。这条与 ADR-0002 的反例（引用高亮）是同一个教训的两面：DOM 补丁只能修补渲染结果，修不了产生结果的语义；区别在于这次真的要换语义，所以选择遮蔽整个入口，而不是在 DOM 上贴补丁。

上游若开出**逐条消息的动作座位**，本插件就可以改为只*添加*一个复制控件，把复刻整行外观的义务整个卸掉。届时这条 ADR 应当作废。
